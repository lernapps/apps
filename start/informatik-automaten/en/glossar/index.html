Glossary

The terms of this app, from A to Z, each with the page that explains it.

automaton

An automaton (plural automata) reacts to inputs and remembers something as it does. What it does depends on the input and on what it has remembered.

Explained on the page Automata in everyday life

complete

An automaton is complete when every state has an arrow for every input.

Explained on the page Designing traffic lights

start state

The start state is the state a machine begins in. In the diagram, the arrow marked “Start” points to it.

Explained on the page State diagrams

state

The state is what a machine remembers right now, for example “€1 paid”.

Explained on the page Automata in everyday life

state diagram

A state diagram (also called a state transition diagram) shows all states of a machine as circles and all transitions as arrows, with their input and output.

Explained on the page State diagrams

test sequence

A test sequence is a series of inputs, starting at the start state. It comes with the state the task says the automaton should end in.

Explained on the page Designing traffic lights

transition

A transition is the jump from one state to the next when there is an input. The next state can also be the same one. In the diagram it is an arrow.

Explained on the page State diagrams

unambiguous

An automaton is unambiguous when every state has at most one arrow for every input. If it is unambiguous and complete, it is called deterministic.

Explained on the page Testing and improving designs
