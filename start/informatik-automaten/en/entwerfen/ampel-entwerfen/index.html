The crossing outside the school

A pedestrian crossing with a button is coming outside the school. The tech club of class 9b builds a model of it, controlled by a small computer. Jona, Selin and Mia, all 14, are in it. Before they write any code, they chat in their group:

Selin: Plan first, code second. What do the lights have to remember?

Jona: Which colour is on. Nothing else.

Mia: And whether someone has pressed! The cars still have green then, but the lights already know.

Selin: Then we design them as an automaton, like our juice machine back in year 6.

On this page you design an automaton yourself and test it. How to read a state diagram is on the page State diagrams.

Exercise

What are the inputs of the crossing?

  • Someone presses the button. right answer

    The button press comes from outside and happens in a moment. That is an input.

  • The time is up. right answer

    A small timer reports “time up”. For the automaton this is an input like the button.

  • The cars have green.

    That stays like this for a while. It is part of a state, not an input.

  • The WAIT light comes on.

    The lights do this themselves when someone presses. That is an output.

Inputs come from outside and set off a transition. Here they are the button and “time up”.

Four steps to an automaton

  1. Collect the inputs: what comes from outside? A small timer outside the automaton counts the time. When it is up, it reports “time up”.
  2. Find the states: what does the automaton have to remember? Two situations that look the same to the cars can be two states: “cars green” and “someone waiting”.
  3. Set the transitions: for every state and every input: where does it go? If nothing changes, the arrow goes back to the same state.
  4. Test: play test sequences and compare where the automaton ends with what the task says.

Outputs such as “WAIT light comes on” can be written at the transitions, as in chapter 1. Here you design only states and transitions.

complete

An automaton is complete when every state has an arrow for every input.

test sequence

A test sequence is a series of inputs, starting at the start state. It comes with the state the task says the automaton should end in.

Here you design class 9b's lights, without a score. Tick the cards that are states. Choose the start state. Then set the target of every row; the diagram draws itself. “Play” shows the way of a test sequence step by step and where it ends: ✓ means as asked, ✗ means somewhere else.

Pedestrian crossing outside the school. At the start the cars have green. If nobody presses the button, it stays like this, even when the time is up. If someone presses the button, the cars keep driving until the time is up. Then the cars get amber; when the time is up again, the green man shows (the cars have red then), then the cars get red and amber, and then green again. During amber, the green man and red and amber, the button changes nothing.

Exercise

Jona says: “For the cars, ‘someone waiting’ is just the same as ‘cars green’. One state is enough.” What happens if class 9b uses only one state?

  • The lights forget the button press or switch to amber without it. right answer

    At “time up” the lights must know whether someone pressed. They can only remember that in a state of their own.

  • Nothing, the lights are the same.

    The lights are the same, but what happens next is different. A state is what the automaton remembers, not what you see.

  • The lights show red for everyone.

    The task gives no reason for that. The problem is the missing memory of the button.

If the same input leads to different things in two situations, they are two states, even if they look the same to the cars.
